for developers

The HTTP API

sonn's public API lives at /api/v1 and is always available — nothing to switch on. It is the contract the web player itself is built on, and nothing else: if the contract can't carry a real player, that's a bug.

Design

Two rules explain every choice below:

  • Reading state never requires polling. Subscribe to /api/v1/events once and you are told about every change. GET /api/v1/zones exists to bootstrap or for one-shot scripts.
  • Commands are plain HTTP. No handshake, no socket, no correlation ids — a curl one-liner or a five-line shell script is a first-class client.

Every successful command is followed by an event, so you never have to read back after writing: zone.changed for anything that alters a zone's state, and queue.changed, favorites.changed or recents.changed for the collections — those say that something changed and leave you to re-read the page you are showing.

The zone object

{
  "id": 3,
  "name": "Kitchen",
  "state": "playing",
  "powerState": { "power": "on", "target": "on", "managed": true },
  "position": 43,
  "duration": 210,
  "volume": 40,
  "volumeLimits": { "max": 70, "default": 20, "step": 2 },
  "repeat": "off",
  "shuffle": false,
  "track": {
    "title": "Song",
    "artist": "Artist",
    "album": "Album",
    "coverUrl": "http://server:7090/streams/3/…/cover",
    "colors": { "primary": [120, 30, 40], "accent": [220, 80, 60], … }
  },
  "source": { "kind": "track", "name": "Library", "id": "library://track/9", "seekable": true },
  "group": { "leader": 3, "members": [3, 7] },
  "output": {
    "protocol": "sendspin",
    "capabilities": { "formats": [{ "codec": "pcm", "sampleRate": 44100, "bitDepth": 24 }], … }
  }
}
Unions are open by design: source.kind, output.protocol and friends accept values your build has never heard of, and unknown event types should be ignored. New ones are not a breaking change — a client that switches exhaustively breaks on a server upgrade.

Reading

# What is playing everywhere?
curl http://server:7090/api/v1/zones

# Follow every change — one subscription, no polling, ever
curl -N http://server:7090/api/v1/events

Commands

# Pause the kitchen, then turn it down a notch
curl -X PUT http://server:7090/api/v1/zones/3/state  -d '{"state":"paused"}'
curl -X PUT http://server:7090/api/v1/zones/3/volume -d '{"volume":"-5"}'

# Play something a zone reported playing earlier
curl -X POST http://server:7090/api/v1/zones/3/play -d '{"id":"library://track/9"}'

# Say something in the kitchen; the music ducks and returns
curl -X POST http://server:7090/api/v1/zones/3/announce -d '{"text":"Dinner!"}'

Volume accepts absolute values and relative nudges ("+5", "-5"), like a remote.

Realtime analysis

Each zone can stream live audio analysis — loudness, spectrum bins, beat strength and pitch — at up to 60 fps, straight off the stream: 

curl -N 'http://server:7090/api/v1/zones/3/analysis?types=loudness,spectrum,pitch&rate=60&bins=48'

Build a VU meter, a wall visualizer, a beat-synced light scene.
